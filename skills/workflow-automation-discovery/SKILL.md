# Workflow automation discovery

Choose a workflow worth fixing before selecting a tool or calling something an agent.

## Map the current process

Follow one real item from trigger to completion. Capture the people involved, systems touched, handoffs, decisions, documents, delays, exceptions, and actual outcome. Prefer a recent example over a hypothetical ideal process.

Quantify the pain with at least one observed or estimated measure: volume, elapsed time, rework, missed revenue, backlog age, error rate, or employee time. Label estimates clearly.

## Decide the right intervention

Use the smallest intervention that resolves the bottleneck:

- A form, database, dashboard, or internal app when the process lacks a system of record.
- A deterministic integration or workflow automation when the rules are stable.
- An AI assistant when the work requires reading, classifying, drafting, summarizing, or extracting from unstructured material.
- A human-approved agent only when multiple steps require contextual judgment and the action can be bounded and recovered.

Do not prescribe an agent merely because AI is available. Reject or defer processes with unclear ownership, no baseline, unavailable data, or unacceptable consequence of error.

## Design the first release

Define the trigger, inputs, source of truth, output, system writes, exception path, accountable owner, and approval boundary. State the minimum data required and who may access it. Identify what happens after a timeout, duplicate event, missing field, or uncertain external write.

## Deliver

Return a one-page recommendation containing:

1. The problem and affected role.
2. The current and proposed workflow.
3. The smallest viable system or automation.
4. Assumptions, risks, and approval boundaries.
5. A baseline metric and a 30-day success metric.
6. A fixed-scope implementation proposal.
